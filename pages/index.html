The missing middle

Building a web app on Google Sheets breaks down the moment it gets real: no accounts, shared links, quotas. The standard advice is jump to a Backend-as-a-Service - but that is a pile of decisions (provider, plan, schema, SDK, auth flows) before a single row of your data ships. nori is the step in between: auth, data, and the backend basics.

Google Sheets

Not made for apps

Shared links instead of accounts, OAuth plumbing when it gets serious, quotas - and one stray edit away from a broken backend.

nori

Auth, data, and the basics

Your spreadsheet as a private backend: accounts and roles, a resource-shaped API, audit trail and backups - nothing else to decide. Self-hosted in one command.

Database / BaaS

Every choice, day one

Provider, plan, schema, SDK, auth flows - powerful, but most of it goes unused while all you need is one table behind login.

Three steps, one binary

One process over one file, durable on every write - that is the whole deployment.

  1. Run it

    Start the binary with a data directory and an admin password.

  2. Import an .xlsx

    Every sheet becomes a table. Column types are detected and every value is validated from then on.

  3. Build on the API

    Humans get sessions, machines get revocable API keys, and the docs are written for your coding agents - Claude Code, Cursor, Codex.

Quick start

      
One file to run - database and dashboard included.


# download the binary for your platform from GitHub Releases, then:
ADMIN_PASS=secret ./nori -addr :8080 -data ./data

# open http://localhost:8080, sign in as admin,
# then import an .xlsx - every sheet becomes a table

      
Prefer building yourself? go build works too, and a Dockerfile is included.
